# ГдеЕдим?

Русскоязычный гастрогид московского района Ново-Переделкино. Гость ищет место на карте и видит, когда сотрудник в последний раз подтвердил наличие столиков. Сотрудник обновляет статус в своём кабинете. Открытая карта опрашивает сервер каждые 4 секунды.

## Запуск на Windows

Откройте PowerShell в папке проекта. При работающем Docker Desktop с Linux-контейнерами выполните одну команду.

```powershell
docker compose up --build
```

Откройте [карту](http://localhost:3000), [кабинет сотрудника](http://localhost:3000/partner) или [администрирование](http://localhost:3000/admin). При первом запуске Compose загрузит образы, применит миграции и перенесёт приложенный снимок каталога в PostgreSQL. Для следующих запусков достаточно `docker compose up`. Данные хранятся в именованном томе. Для остановки используйте Ctrl+C или `docker compose stop`.

**Вариант без Docker.** На компьютере с Node.js 24 и PostgreSQL 17 выполните `npm.cmd run local`. Скрипт сам установит npm-зависимости, подготовит сборку и отдельную базу в `.local/native`. Системный сервер PostgreSQL и его пароль не нужны. Сайт доступен по тому же адресу. Для нестандартной установки задайте `GDE_POSTGRES_BIN` — путь к папке с программами PostgreSQL. Для первого запуска понадобится интернет, затем карта и каталог работают локально. После изменения исходников выполните `npm.cmd run build` и перезапустите приложение. Выберите один способ запуска для порта 3000.

## Первый администратор и первый партнёр

В другом терминале создайте первого администратора. Подставьте свой адрес.

```powershell
docker compose exec app npm run admin -- owner@example.org
```

При запуске без Docker соответствующая команда — `npm.cmd run local -- admin owner@example.org`. Консоль один раз покажет случайный пароль. Сохраните его. Создать таким способом второго администратора в той же базе нельзя.

1. Сотрудник открывает «Войти», создаёт аккаунт, раскрывает «Я сотрудник заведения», выбирает своё заведение и отправляет заявку.
2. Администратор проверяет полномочия сотрудника у заведения. В разделе «Сотрудники» выбирает запись и сохраняет назначение. Чтобы отозвать доступ, выбирает «Без доступа сотрудника».
3. Сотрудник открывает `/partner`, при необходимости указывает размер компании и нажимает один из трёх статусов. У гостя обновляется карточка без перезагрузки. По умолчанию через 30 минут появляется «Нет свежих данных». Срок задаёт `AVAILABILITY_TTL_MINUTES`.
4. Для предложения сотрудник задаёт описание, условия, промокод, даты по Москве и лимит. После одобрения администратором на карте появляется описание. Изменение условий возвращает предложение на проверку.
5. Подписчик получает код и персональный номер выдачи. Повторное открытие доступно в аккаунте в «Мои промокоды». Сотрудник вводит номер в своём кабинете и погашает код один раз. В кабинете видны отдельно количество выданных и погашенных кодов.

## Каталог и повторный импорт

Снимок от **23 ноября 2026 года** содержит **11 заведений** — 5 ресторанов, 4 кафе и 2 кофейни. Адрес найден для 10 заведений, режим работы — для 5. Это сведения из OpenStreetMap на дату проверки. Охват зависит от разметки OSM. Безымянные точки требуют проверки. Бары, фастфуд и магазины зерна без подтверждённой подачи кофе исключены. Даты означают сверку с OSM. Партнёрство и статусы столиков ведутся отдельно. [Граница района, relation 446117](https://www.openstreetmap.org/relation/446117) · [Авторство и лицензия ODbL](https://www.openstreetmap.org/copyright)

Импорт сверяет административный уровень и идентификатор района, собирает внешние и внутренние кольца границы, загружает точки, линии и отношения. Скрипт проверяет покрытие выгрузки, отбирает записи по геометрии и сохраняет исходные идентификаторы, ссылки, источники адресов и даты. Сведения о совпадениях, пропавших и закрытых объектах попадают на проверку. Подозрительные записи можно сверить с источником, связать с основной записью или скрыть в разделе «Каталог». Каждое решение сохраняется в журнале.

Для обновления из OSM и переноса результата в работающую базу выполните:

```powershell
docker compose exec app npm run import:osm
```

Чтобы перенести уже готовый снимок из контейнера в базу повторно, используйте `docker compose exec app npm run import`. Чтобы сохранить обновлённые исходные файлы в проект, выполните `docker compose cp app:/app/data/catalog.json ./data/catalog.json` и `docker compose cp app:/app/data/boundary.geojson ./data/boundary.geojson`. Для режима без Docker используйте `node scripts/osm.mjs`, затем `npm.cmd run local -- import`. Повторный импорт сохраняет назначения сотрудников, их обновления, предложения и решения модератора. Подложка района поставляется вместе с приложением. [Сборка карты](карта.md)

## Показ за две минуты

**Подготовка до выступления.** Запустите отдельный учебный экземпляр. Каталог реальных заведений останется на порту 3000, учебная карта откроется на порту 3001. У экземпляров разные схемы базы и разные cookie.

```powershell
docker compose --profile demo up --build -d
docker compose exec demo npm run demo
```

Команду создания учебного сотрудника выполните один раз. Она выдаёт случайный пароль для `partner@demo.local` и создаёт одобренное предложение «Учебный десерт к обеду». Вариант без Docker — сначала `npm.cmd run local -- --demo demo`, затем `npm.cmd run local -- --demo`.

Откройте [учебную карту](http://localhost:3001) и [учебный кабинет](http://localhost:3001/partner) в разных профилях браузера или в обычном и приватном окне. В кабинете войдите сотрудником. В гостевом окне заранее создайте новый обычный аккаунт для показа пробного периода.

| Время | Что показать |
| --- | --- |
| 0:00–0:25 | На учебной карте найдите «Учебное бистро», нажмите сердечко и откройте избранное. Покажите исходное «Нет данных». |
| 0:25–0:55 | В кабинете выберите «Есть свободные столики». Переключитесь в гостевое окно. На открытой карте появятся статус, источник и время обновления. |
| 0:55–1:25 | Откройте Плюс, покажите цену 299 ₽ в месяц и ручное продление. Подтвердите условия и включите 14 бесплатных дней. |
| 1:25–2:00 | В карточке бистро получите учебный промокод. Скопируйте номер выдачи в кабинет сотрудника и нажмите «Погасить код». Покажите счётчик погашений. |

Время жизни статуса в автотесте сокращено. На реальной карте действует срок из конфигурации. В учебном режиме используются только вымышленные записи.

## Подписка и ЮKassa

Карта, избранное и сведения о столиках бесплатны. Плюс открывает партнёрские предложения на 14 дней, затем пользователь вручную оплачивает месяц за 299 ₽. Приложение не хранит данные банковских карт. Каждый платёж требует отдельного согласия.

Для настоящего тестового платежа скопируйте `.env.example` в `.env` и заполните `DEMO_YOOKASSA_SHOP_ID` и `DEMO_YOOKASSA_SECRET_KEY` реквизитами **тестового** магазина. Команда `docker compose --profile demo up -d demo` применит конфигурацию. В режиме запуска Node.js используйте имена переменных из инструкции интеграции. Дубликаты уведомлений не зачисляют второй месяц. Переход на страницу возврата запускает серверную сверку. Окончательное решение принимает сервер по подтверждённому платежу. [Настройка оплаты, уведомлений и чеков](оплата.md)

## Авторизованный счётчик

Оператору нужны разрешение заведения на передачу агрегированной численности и подтверждённая вместимость. Сначала назначьте сотрудника заведению. По его идентификатору из каталога и подтверждённой вместимости создайте или замените ключ в серверной консоли.

```powershell
docker compose exec app node scripts/manage.mjs counter ИДЕНТИФИКАТОР ВМЕСТИМОСТЬ
```

Консоль однократно выводит ключ. Передайте его авторизованному устройству защищённым способом. В базе хранится хеш. Для отзыва выполните `docker compose exec app node scripts/manage.mjs revoke-counter ИДЕНТИФИКАТОР`.

Устройство отправляет `POST /api/counter` с заголовками `Authorization: Bearer <ключ>` и `Content-Type: application/json`. Тело содержит только `people` (целое число) и `timestamp` (время измерения Unix в миллисекундах). Например, устройство формирует тело выражением `JSON.stringify({people: 18, timestamp: Date.now()})`. Сервер проверяет ключ, вместимость, давность и порядок измерений. При 18 людях и вместимости 30 карточка показывает «Оценка заполненности: 60%». Источник подтверждения столиков — отдельная кнопка сотрудника.

## Проверки

Рабочая сборка проходит `npm.cmd run build`. Для тестов нужен PostgreSQL 17 и тестовая роль с правом создавать временные базы и схемы. Вне Docker укажите подключение в `TEST_DATABASE_URL`. Тесты используют уникальные имена и убирают свои временные данные. В локальном Compose необходимые права уже есть.

```powershell
docker compose exec app npm test
```

При запуске без Docker те же тесты выполняет `npm.cmd run local -- test`. Эта команда сама передаёт реквизиты локальной базы тестовому процессу.

Для браузерного сценария из папки проекта установите зависимости командой `npm.cmd ci`, выполните `npm.cmd run build`, укажите тестовое подключение. Установите Chromium командой `npx.cmd playwright install chromium` или укажите путь к существующему Chromium/Edge в `BROWSER_EXECUTABLE`. Запустите `npm.cmd run test:browser`. Сценарий самостоятельно поднимает учебный сервер на свободном порту.

Проверяются реальная граница и импорт, изоляция сотрудников, недоступность администрирования гостю, избранное и фильтры, сквозное обновление и истечение статуса, отклонение невозможных показаний счётчика, пробный период, ручная оплата, повторные уведомления, лимит и однократное погашение кода. В платёжных автотестах PostgreSQL настоящий, ответы ЮKassa подменяет тест. Для проверки обмена с ЮKassa понадобятся реквизиты магазина.

## Размещение после согласования

Приложение использует Next.js, TypeScript, Node.js 24 и PostgreSQL 17. GitHub Pages раздаёт статические файлы. Кабинетам, авторизации и проверке платежей нужен процесс Node.js, постоянная база и доступный для ЮKassa HTTPS-адрес.

1. Выберите сервер с Docker и постоянным хранилищем для PostgreSQL либо подключите управляемую PostgreSQL через `DATABASE_URL` в окружении приложения. Создайте резервную копию и проверьте восстановление перед открытием доступа.
2. Настройте домен и HTTPS-прокси к локальному порту приложения. Для Compose задайте `APP_PUBLIC_URL=https://ваш-домен`, для отдельного Node.js — `PUBLIC_BASE_URL`. Этот адрес используется для проверки источника запросов и возврата из оплаты. PostgreSQL в локальном Compose использует общий Unix-сокет без открытого TCP-порта.
3. Соберите приложение, запустите `npm run setup` для миграций и каталога, затем `npm start`. В Docker эти действия уже описаны в образе. Создайте первого администратора и подтвердите полномочия сотрудников до назначения заведений.
4. Для подключения рабочего магазина согласуйте выдачу чеков и настройте уведомления. Для реальных показаний счётчика получите разрешение и параметры оборудования. Учебный экземпляр оставьте отдельным.
